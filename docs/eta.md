# 剩余时间（ETA）原理与排查

## 1. 优先级

从高到低：

1. **可识别的实时进度**：tqdm、`Epoch 65/80`、`step 1200/5000`、`fold 22/50`、单独成行的 `500/7442`、`45%`；
2. **手动总时长**：右键 → 设置预计总时长（`90` 表示分钟，也支持 `90m`、`1.5h`、`2h30m`、`1:30`）；
3. **历史运行中位数**：同一个“文件夹 + 脚本”至少完整跑完一次后，下次直接用历史中位数；
4. **启动以来平均速度**：有进度但还不足两次采样时，用“已完成 / 已运行”粗估（低置信度）。

暂停期间 ETA 与已运行时间一起冻结，继续后继续推进。

## 2. 日志发现顺序

`progress.discover_log()` 依次尝试：

1. **命令行重定向**：当前进程和最多 4 层父进程的 `>`、`tee`、`--log-file`、`-o` 等；
   - Git Bash 路径：`/d/项目/x.log` → `D:\项目\x.log`，`/tmp/x.log` → `%TEMP%\x.log`；
   - 带 shell 变量的文件名（如 `/tmp/kd5_meld_$s.log`）会展开成实际存在的文件；
   - 多个候选时结合 `--seed`、脚本名和修改时间选最匹配的。
2. **目录扫描**：工作目录、脚本目录、项目目录、它们的 `logs/` / `log/` / `runs/` / `results/` / `outputs/` 子目录；
   - 只接受进程启动后修改过的文件；
   - 离工作目录越近的日志权重越高，避免误用兄弟实验的同名 `train.log`；
   - 先按文件名/目录/时间打分，再对最有希望的若干文件读取尾部确认是否真有可识别进度。
3. 手动指定：右键 → 指定进度日志；
4. 手动总时长：右键 → 设置预计总时长。

## 3. 支持的进度格式

| 格式 | 例子 | 说明 |
| --- | --- | --- |
| tqdm | `57%|████| 4/7 [00:05<00:03, 1.24s/it]` | 取当前/总数，tqdm 自带的剩余时间优先（没有外层 epoch 时） |
| Epoch / Step | `Epoch 3/50`、`step 1200/5000` | 命名进度 |
| fold / seed / round | `fold 22/50`、`fold 41/58 done` | 常见的批量实验格式 |
| 裸分数 | `500/7442` 单独成行 | 要求总数 ≥ 20，避免误匹配 |
| 百分比 | `progress: 45%`、带进度条字符的百分比 | 需要上下文或进度条字符 |
| 自定义 | 见下方 `custom_progress_rules` | 正则命名捕获 |

## 4. Epoch 内进度 → 整体进度

大量训练脚本的 tqdm 只表示**当前 epoch 内**的 batch 进度：

```text
Epoch 65, CLS 0.8030:  57%|████████    | 4/7 [00:05<00:03, 1.24s/it]
```

如果命令行有 `--epochs 80`（或日志里能读到 `epochs=80`），程序会换算：

```text
(65 - 1 + 4/7) / 80 = 80.7%
显示：Epoch 65/80 · 57%
```

这样不会再把“当前 epoch 还剩 3 秒”误报成整个实验的剩余时间。

补充规则：

- 如果日志已经写了 `Epoch 65/80`，直接当整体进度；
- 如果知道总 epoch 但日志里定位不到当前 epoch，则**不使用** epoch 内 tqdm 的剩余时间，回退到手动 / 历史 / 未知，避免误报；
- 支持从命令行提取 `--epochs`、`--num_epochs`、`--max_epochs`、`--n_epochs`；也支持日志里的 `epochs=80`。

## 5. 为什么显示“剩余未知”

自动估算至少需要：**实时可识别进度**、**手动总时长**、**历史运行记录** 之一。

常见原因：

1. **没有进度日志**：实验没有重定向，日志写在别处；
2. **日志里没有可识别进度**：只有 warning、loss 或 `fold done`（没有总数）；
3. **日志不更新**：stdout 被缓冲，或实验卡在长时间计算中（例如 `meld_run.py` 的 `queue.log` 只有启动信息和警告，1 个多小时没更新）；
4. **第一次运行**：没有历史记录，日志又不足两次采样；
5. **日志读不到**：被进程锁定、路径不存在、变量没有展开；
6. **总 epoch 已知但当前 epoch 位置无法确定**：程序会保守地不用 epoch 内 tqdm 的剩余时间。

把鼠标悬停在“剩余未知”上会显示具体原因；也可以运行：

```powershell
python tools/diagnose_eta.py
```

它会为当前每个实验打印：

- 找到的日志路径；
- 是否来自命令行重定向；
- 解析到的进度 / 速率；
- 估算依据或未知原因；
- 日志最后几行。

## 6. 让 ETA 更准的建议

1. 让脚本输出带总数的进度，例如：

   ```python
   print(f"fold {i}/{total} done", flush=True)
   ```

2. 使用 `python -u`，或在 `print` 后 `flush=True`，保证日志及时落盘；
3. 多 epoch 训练在命令行保留 `--epochs N`，方便程序换算整体进度；
4. 第一次跑完会写入历史，下次同“文件夹 + 脚本”的实验会自动有历史 ETA；
5. 没有日志时，右键手动设置总时长。

## 7. 自定义进度规则

如果日志格式特殊，在 `data/config.json` 的 `estimate.custom_progress_rules` 中增加规则：

```json
{
  "estimate": {
    "custom_progress_rules": [
      {
        "name": "fold",
        "pattern": "(?P<cur>\\d+)\\s*/\\s*(?P<total>\\d+)\\s+folds?"
      },
      {
        "name": "my-pct",
        "pattern": "progress:\\s*(?P<pct>\\d+(?:\\.\\d+)?)%"
      }
    ]
  }
}
```

规则必须包含：

- `(?P<cur>…)` + `(?P<total>…)`，或
- `(?P<pct>…)`（0–100）。

## 8. 与暂停的关系

- 暂停时 ETA 和已运行时间冻结，不会因为挂起而继续减少；
- 继续后按恢复后的真实运行时间推进；
- 如果实验在暂停期间被外部结束，不写入历史记录（避免污染历史中位数）。
